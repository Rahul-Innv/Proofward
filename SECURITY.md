# Security policy

## Reporting a vulnerability

Please do not publish vulnerability details in a public work item.

Open the GitLab [new issue form](https://gitlab.com/krahul02004/Proofward/-/issues/new),
mark the issue **confidential**, and include only the minimum information needed to reproduce and
assess the problem. If confidential reporting is unavailable, submit a detail-free request for a
private contact channel instead.

Public, non-security reports can be reviewed in the
[work-item list](https://gitlab.com/krahul02004/Proofward/-/work_items).

## Supported state

The current `main` branch is supported. Proofward is a documentation-only umbrella; report a
vulnerability in a child tool to that tool's repository so its code owner and security policy apply.

Never include credentials, tokens, private transcripts, customer data, or unredacted local paths in
a report. Rotate any credential that may have entered a commit, log, artifact, or transcript.
